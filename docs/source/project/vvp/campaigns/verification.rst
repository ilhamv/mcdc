======================
Verification Workflows
======================

The multigroup fixed-source, multigroup eigenvalue, and multigroup code-to-code
suites share a launch/process interface but vary different
sampling quantities and use different references.
They test the shared, particle-agnostic multigroup transport formulation.
Paths in the commands below refer to the MC/DC-VVP suite directories.
The :doc:`verification overview <../verification/index>` introduces the suites
and links to their case catalogs and convergence evidence.
Paths below are relative to the MC/DC-VVP repository root unless a suite working
directory is specified.

.. _vvp_run_fixed_source:

Multigroup fixed-source suite
-----------------------------

Use ``verification/analytical/multigroup/fixed_source`` for steady-state and transient
multigroup cases, including slab, AZURV1, and infinite-medium SHEM-361 problems.
Each case has ``input.py``, ``reference.py``, ``process.py``, and ``plot.py``.
Shared cross sections are stored in the suite's ``data/`` directory.

A ``task.yaml`` entry selects a case and a logarithmic particle-count sequence:

.. code-block:: yaml

   azurv1:
     logN_min: 5
     logN_max: 7
     N_task: 7
     walltime: 0.27

The required ``walltime`` requests hours for the whole case job; a launch-level
override applies uniformly. Record the calibration basis in task comments.

The runner generates counts using
``numpy.logspace(logN_min, logN_max, N_task, dtype=int)``.
Here the seven counts range from 100,000 to 10,000,000.
One task is one execution at one count; each case's runner executes those tasks
sequentially. The study checks for relative errors decreasing as
:math:`N^{-1/2}`.

From this suite directory:

.. code-block:: console

   python launch.py

For HPC execution, use the alternative launch:

.. code-block:: console

   python launch.py --platform tuolumne --N_node 1 --walltime 1.0

After completion:

.. code-block:: console

   python process.py

Pass ``maestro_run_<timestamp>`` as a positional argument to process a particular
study. The processor writes convergence figures to ``results/convergence/`` and
largest-particle-count comparisons to ``results/comparison/``.
Time-dependent comparisons use GIF animations.
The root processor subsequently collects these under the same suite path in the
repository-wide ``results/`` tree.

The SHEM-361 dataset was generated by homogenizing a continuous-energy calculation
of an infinite lattice of borated PWR fuel pin cells onto the SHEM-361 group
structure. Its provenance and the mathematical references are described on the
:doc:`SHEM-361 case page <../verification/analytical/multigroup/fixed_source/inf_shem361>`.
The :doc:`manufactured two-group slab <../verification/analytical/multigroup/fixed_source/mms_two_group_slab>`
page gives the source construction and analytical flux.

.. _vvp_run_eigenvalue:

Multigroup k-eigenvalue suite
-----------------------------

Use ``verification/analytical/multigroup/k_eigenvalue`` to compare multiplication
factors and fundamental-mode fluxes for homogeneous slabs, the Kornreich-Parsons
slab, and infinite SHEM-361 cases.
The common case files and launch/process commands match the fixed-source suite.
The multigroup inputs use ``../fixed_source/data/SHEM-361.npz`` relative to this
suite.

Tasks vary active cycles rather than particles per cycle:

.. code-block:: yaml

   one_group_slab:
     N_active_min: 20
     N_active_max: 2000
     N_task: 5
     walltime: 0.21

Counts are generated with
``numpy.rint(numpy.geomspace(N_active_min, N_active_max, N_task)).astype(int)``.
Particles per cycle and inactive cycles remain fixed in ``input.py``.
Choose those fixed values through a preliminary source-convergence and variance
study before interpreting an active-cycle campaign.
The convergence check uses :math:`N_\mathrm{active}^{-1/2}`.

``results/convergence/`` contains active-cycle convergence and uncertainty plots;
``results/comparison/`` contains the highest-statistics flux and cycle histories.
To inspect one output from the suite directory:

.. code-block:: console

   python cases/inf_shem361_subcritical/plot.py cases/inf_shem361_subcritical/output_2000.h5

.. _vvp_run_code_to_code:

Multigroup code-to-code suite
-----------------------------

Use ``verification/code_to_code/multigroup/fixed_source`` for comparisons among independently
implemented codes. The supplied cases use MC/DC and OpenMC and cover C5G7 and
Kobayashi transients, including moving geometry, delayed neutrons, void streaming,
and space-time tallies.
Each case supplies the same four common files, but ``reference.py`` retrieves
external participating-code data instead of constructing an analytical solution.

Particle-count tasks use the fixed-source ``logN_min``, ``logN_max``, and
``N_task`` schema. The supplied inputs use 30 batches and vary particles per batch;
processing reads the actual batch count and computes total histories.
A case's largest particle-count output and the corresponding participating-code
outputs supply one fixed comparison reference.

Before processing, download and checksum the canonical OpenMC statepoints from
the suite directory:

.. code-block:: console

   python cases/c5g7-4phase/reference.py
   python cases/kobayashi/reference.py

These files are external comparison data and are not tracked in MC/DC-VVP.
For the Kobayashi detector variant, supply detector-specific reference outputs:
its ``reference.py`` still identifies the baseline Kobayashi archive as a
placeholder. Baseline flux statepoints do not establish a detector-capture
comparison.

Launch and process from the suite directory with the same commands as the
analytical suites. Completed outputs are skipped on relaunch; missing particle
levels are run. Use :doc:`running` for the distinction between resuming an
unchanged campaign and starting a new one.

The processor produces:

- ``results/convergence/``: pair-averaged relative 2-norm and maximum absolute
  pairwise relative-difference curves.
- ``results/reference/``: fixed-reference figures or animations from the
  arithmetic mean of the largest-sample participating estimates.
- ``results/comparison/``: largest-shared-sample comparison and relative-difference
  plots. Spatial cases produce animations; detector histories produce static
  plots.

For example, inspect a baseline Kobayashi sampling point using its largest-sample
results as reference:

.. code-block:: console

   python cases/kobayashi/plot.py \
       cases/kobayashi/output_100000000.h5 \
       cases/kobayashi/reference/output_0.h5 \
       cases/kobayashi/output_10000000000.h5 \
       cases/kobayashi/reference/output_4.h5

The :doc:`code-to-code discussion <../verification/index>` and its linked case
pages explain the normalization, statistical interpretation, and limits of
agreement between codes.
